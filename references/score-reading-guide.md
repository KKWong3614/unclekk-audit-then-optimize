# B / C / A 分数速读指南 — 30 秒看懂，不再绕

> 报告里大家最纠结的就是 A、B、C 三个分数。本文件把它讲成人话。
> The three scores A/B/C confuse most users. This is the plain-language version.

---

## 一句话卡片（背这个就够了）

```
A = 优化前的独立审计分（基线，看「有没有进步」）
B = 优化器的自评分（乐观分，几乎必然偏高，**别当真**）
C = 优化后的独立复审分（权威分，**最终以它为准**）
```

> **铁律**：优化后，同一量规下 **C 是权威分，不是 B**。所有纠结先回这条。

---

## 决策表（ASCII，照着查）

```
            B − C 的差值怎么读？
┌─────────────────────────────────────────────────────┐
│  B − C >  +3   │ 自评分虚高        │ 丢弃 B，以 C 为准 │
│  C − B >  +3   │ 别急着否定 C     │ 先重核实 C 的     │
│                 │ （可能量规/基线   │ 基线/量规是否和 B │
│                 │  不同，非你更牛）│ 一致，再决定      │
│   |差值| ≤ +3   │ 小幅波动        │ 主代理交叉核对即可 │
└─────────────────────────────────────────────────────┘
```

> ⚠️ 规则是**有方向的**，不是「差>3 就否定」：
> - B 比 C 高很多 → 是你自己吹高了，信 C。
> - C 比 B 高很多 → **不是**你更牛，是审计员可能用了不同基准，先查再信。

---

## 3 个数值场景（看完就懂）

### 场景 1：B 比 C 高 4 分 → 自评分虚高，信 C

```
A = 68   B = 86   C = 82
B − C = +4  →  > +3
判定：优化器自评 86 是虚高，真实水平看 C = 82。
行动：用 C 的 4 条发现做权威修复清单，不要看 B 的。
进步：A(68) → C(82)，真实 +14（不是优化器吹的 +18）。
```

### 场景 2：C 比 B 高 6 分 → 别自动否定 C，先查

```
A = 70   B = 82   C = 88
C − B = +6  →  > +3
判定：先别高兴。C 更高可能是审计员用了不同基线/量规。
行动：重读 C 的评分标准，确认和 B 是同一把尺；一致才采纳 C。
（若量规混用 /100 与 /90，先转成相对百分比再比，见 SKILL.md 评分约定）
```

### 场景 3：B 与 C 只差 2 分 → 主代理核对即可

```
A = 75   B = 84   C = 82
B − C = +2  →  ≤ +3
判定：小幅波动，属正常方差。
行动：主代理交叉核对 C 的发现，没大问题就收工。权威分 = C = 82。
```

## 常见误解（避坑）

| 误解 | 正解 |
|---|---|
| "C 比 B 高，说明我优化得比自己想的还好" | 不一定，先查 C 的基线/量规是否和 B 一致 |
| "B 就是最终分" | 错，B 是乐观自评分，最终以 C 为准 |
| "A 没用，只看 B 和 C" | A 是进步标尺（A→C 看真实增益），不能丢 |
| "元技能自己量的分最准" | 元技能有自指死锁，「真实测试」维度退化为 dry_run，C 用主代理人工核对代替机器分 |

> 多轮闭环里，审计员自己的复审分只是**自检**，不算独立 C；真正独立 C 由主代理轮后验证提供。
